# WFX-053 — Environment-Variable Inventory

**Status:** canonical inventory, defined 2026-09-15 (WFX-053). Every variable name that the productionization track (WFX-050–059) consumes, its purpose, and its owning lane. Names are canonical; VALUES never live in this repository — they live in the operator secrets store (`/home/z/.secrets/env`, `/home/z/.secrets/wfx-infra.json`) and, at deploy time, in the platform's env-var store (Vercel project settings — WFX-056).

The names below are mirrored in [`.env.example`](../../.env.example) at the repo root, which is the executable checklist for local/preview setup (comments only, no values).

## Conventions

- **App-runtime variables** are read by `apps/web` / `packages/*` at request time. They must be safe to expose to the server runtime of the web host and are provisioned into the Vercel project environment by WFX-056.
- **Tooling variables** (provisioning, CI, deploy) are NEVER app runtime variables. They are used from operator shells or CI secrets only. Mixing the two classes is a security violation (a leaked deploy token must not imply database access, and vice versa).
- Optional integrations follow the **pair contract**: presence of the full env pair enables the integration; absence triggers the documented typed fallback (see [degradation-behavior.md](./degradation-behavior.md)). The app never assumes an optional resource exists.

## Required app-runtime variables

| Name | Purpose | Consuming lane / items |
|---|---|---|
| `DATABASE_URL` | Neon PostgreSQL connection string for the `webflix` database. **Pooled endpoint** (`-pooler` host, PgBouncer transaction mode) — the runtime default for app queries. (The direct endpoint string is held by the operator for migrations/DDL only; see notes below.) | Lane B — WFX-052 (persistence + auth packages), WFX-054 (sources backend). Read by the data layer at boot; failure to connect is a typed startup error, never a silent fallback to fixtures. |
| `APP_ENCRYPTION_KEY` | Application-level encryption key (32-byte secret, base64 or hex) used to encrypt credentials at rest in Postgres (e.g. YouTube OAuth tokens stored by the connector registry, WFX-012/WFX-054) and any sensitive columns. Generated by the operator before first production deploy. | Lane B — WFX-052 (secure credential storage), WFX-054 (YouTube connector token persistence). Missing key + non-empty credentials table must be a typed startup error, not plaintext fallback. |
| `R2_S3_ENDPOINT` | Cloudflare R2 S3-compatible API endpoint (account-level URL, e.g. `https://<account>.r2.cloudflarestorage.com`). | Lane C — WFX-053 provisioning; app media read/write (WFX-056+ runtime). |
| `R2_ACCESS_KEY_ID` | R2 S3 access key id (SigV4). | Same as above. |
| `R2_SECRET_ACCESS_KEY` | R2 S3 secret key (SigV4). | Same as above. |
| `R2_BUCKET` | Bucket name for application object storage: `webflix-media`. (Name-only config — safe to log.) | Lane C/B — media artifacts, exports, telemetry blobs. |

## Notes

- `DATABASE_URL` pooled vs direct: the runtime uses the pooled endpoint (transaction-mode pooling is correct for serverless request handlers and counts as ONE connection class toward Neon). Migrations/DDL that require session semantics (advisory locks, `LISTEN/NOTIFY`, multi-statement prepared sessions) use the direct endpoint — the operator holds that string in `/home/z/.secrets/wfx-infra.json`; if a migration runner needs it at deploy time it is injected as a separate, non-default variable (e.g. `DIRECT_DATABASE_URL`) by WFX-056, never overwriting `DATABASE_URL`.
- Secret hygiene: rotate-by-redeploy is the model — all secrets above can be replaced in the platform env store and the app re-reads them at boot. No secret is ever baked into a build artifact or a client bundle (client-exposed config is a separate, explicit allow-list in the web host lane).
