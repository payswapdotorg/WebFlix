# @wfx/torrent-engine — R11

The Torrent Engine for WebFlix's native-media path: authorized magnet and
`.torrent` ingestion, metadata, file selection, sessions, peer/piece state,
integrity verification, pause/resume, persistent recovery, and a narrow
native-media adapter. The BitTorrent protocol lives INSIDE the wrapper
(invariant 6 of the remediation freeze) — the package's PUBLIC surface
speaks WebFlix types only (sessions, selections, verdicts — no
wire-protocol types leak).

## The authorization law (invariant 5)

> Native acquisition is limited to user-owned, licensed, public-domain,
> Creative Commons, or otherwise authorized media. The engine is
> AUTHORIZED-SOURCE-ONLY: an ingestion carries its authorization
> provenance (which authorized source/vault it came from); unprovenanced
> ingestion is a TYPED REJECTION, not a warning.

**Structural enforcement.** The public ingestion API is `ingestMagnet(uri,
provenance)` + `ingestTorrentFile(bytes, provenance)`. The `provenance`
argument is a branded nominal type (`Provenance`) whose ONLY constructor is
`provenanceFromAuthorizedSource` — TypeScript rejects every call site
that does not supply a branded `Provenance`. The runtime mirror
(`isProvenance`) refuses every non-branded value defensively (the
`UNAUTHORIZED_SOURCE` typed rejection). The frozen `TorrentSource.authorized:
boolean` field is derived (set to `true` at the seam) because provenance
was structurally proven.

The closed authorization vocabulary (5 kinds):

| Kind               | Meaning |
|--------------------|---------|
| `user-owned`       | The user owns the media (a personal rip of a DVD/BD they own; home video they created). |
| `licensed`         | The user holds a license that permits native acquisition (DRM-free purchases, downloads from a licensed storefront that permits offline copies). |
| `public-domain`    | The media is in the public domain. |
| `creative-commons` | The media is released under a Creative Commons or comparable permissive license that permits native acquisition. |
| `authorized-vault` | The media comes from an authorized vault the user has wired into WebFlix (a personal NAS, a media library they have declared authorized, a connector-supplied authorized catalog). |

## The mature-library boundary (invariant 6)

> WebFlix does NOT reimplement BitTorrent in product-core TypeScript. Use
> a MATURE protocol implementation.

**Evaluation.** The primary candidate is `webtorrent` (v2.8.5, MIT) —
mature, MIT-licensed, runs under Bun/Node, wired for both `.torrent` and
magnet, handles the peer protocol + DHT + ut_metadata + PEX in its
`WebTorrent` class. The PARSE primitive is `parse-torrent` (v11.0.24, MIT,
webtorrent's parsing sub-package) — used DIRECTLY by `metadata.ts` for
magnet and `.torrent` parsing. The SWARM primitives (peer discovery,
piece exchange, integrity) are abstracted behind the `BitTorrentBackend`
interface (see `src/backend.ts`).

**Pin.** `parse-torrent@^11.0.0` is the package's runtime dependency. The
parsing primitives are exercised in tests against committed fixture
metainfo (`tests/fixtures/sintel-single.torrent` + `.magnet.txt` + `.bin`
+ `.summary.json`, regenerated by `bun run scripts/build-fixtures.mjs`).

**Sandbox limitation (honest, documented).** The sandbox cannot build
`webtorrent`'s optional `node_datachannel` native module, so the production
backend wraps the library behind the `BitTorrentBackend` interface but
the DEFAULT backend in this codebase is the `LoopbackBitTorrentBackend`
(deterministic, no network — the spec's "documented testing mode" for
sessions). The production deployment must install `webtorrent` (or a
comparable mature implementation) and inject it through `BitTorrentBackend` —
the engine boundary keeps the choice swappable without touching the public
API.

**Secondary candidates evaluated, not chosen:**

- `libtorrent` (C++, not Bun/Node-native without FFI).
- `transmission` (C, requires a subprocess + IPC).
- `aria2` (C, JSON-RPC over a subprocess).

## The session lifecycle

The frozen `TorrentState` union (from `@wfx/domain`):
`metadata | checking | buffering | playing | downloading | paused | complete | failed`.
The transition table (see `src/session.ts`):

```text
metadata ──> checking ──> downloading ⇄ paused ──> complete
                │           │
                ▼           ▼
              failed <── (every live state)

(playing is a playback-driven projection the engine surfaces when the
playback-aware scheduler (R12) reports the playhead inside a downloaded
range; it is reachable from downloading and paused and never terminal.)
```

**The honest status projection** (`statusFromSession` in `src/session.ts`)
reports a runtime status that names the stall truthfully:

- `discovering-metadata` — magnet source, metadata not yet acquired.
- `selecting` — metadata arrived, the user has not yet chosen a file.
- `downloading` — pieces are arriving.
- `seeding-paused` — the session is paused with verified pieces.
- `verifying` — the engine is hashing the final bytes against the recorded
  piece hashes + computing the asset digest.
- `completed` — integrity proven, asset landed.
- `failed(reason)` — the honest failure (with a reason).

A session with `peerCount === 0` for the configured stall window reports
`failed(stalled)` — NEVER a fake "downloading" progress.

## Recovery / journal semantics

The recovery journal (`src/journal.ts`, the R10 discipline mirrored):

- `<dataRoot>/torrent-journal.ndjson` — append-only, one JSON record per line.
- Record types: `ingest` (the authorization + magnet/.torrent infohash +
  file selection), `control` (pause/resume/stop/select-files with the
  resulting verified-piece count), `state` (observed session state with
  optional structured evidence), `evidence` (engine-level facts).
- **Control-point journal, not a telemetry log.** Every control command is
  journaled with its resulting verified-piece count; per-piece download
  ticks are NOT journaled. Recovery resumes from the last JOURNALED control
  point — the honest last-known-PERSISTED verified count.
- **Torn-tail tolerance.** A crash mid-append leaves a partial final line;
  `readAll` drops it (every record that provably landed replays).
- **Recovery extraction is pure.** `extractRecoverableSessions` is a pure
  function of the record list: a session is recoverable iff it was
  ingested, was NOT stopped, and its last known state is non-terminal.
- **Sequence numbers survive restarts.** The in-memory counter is seeded
  from the file's maximum `seq`, so a restarted engine continues the
  sequence without reuse.
- **HONEST FAILURE FOR VANISHED STATE** (the R10 law, mirrored). A session
  whose data directory disappeared is NOT silently restarted from zero
  pretending continuity — recovery reports the session as `failed` with
  the `DATA_VANISHED` evidence. The engine surfaces the honest detail; the
  caller decides whether to re-ingest.

## The native-media adapter (the narrow seam)

`src/adapter.ts` is the ONLY module in `packages/torrent-engine/src/` that
imports from `@wfx/native-media`. The adapter feeds VERIFIED completed
selections into the R10 engine's asset store (bytes land as native-media
assets with digests + integrity verdicts), so the desktop's NATIVE rung
plays torrent-acquired media through the SAME range gateway as local files.

**Boundary guard** (`tests/import-guard.test.ts`): every OTHER module in
`packages/torrent-engine/src/` must NOT import from `@wfx/native-media` —
the native-media surface is unreachable from torrent-engine outside the
adapter. The lane checker (`scripts/check-lanes.mjs`) enforces the
cross-package import law (no deep paths, only public entries); this test
enforces the torrent-engine-LOCAL boundary law.

**Honesty laws** (mirrored from R10's asset store):

1. **DIGESTS ARE REAL.** The adapter imports the verified asset's SHA-256
   from the engine; the asset store's `importAsset` re-hashes the bytes as
   they land (the SAME primitive — no fabrication, no leak).
2. **VERIFIED ONLY.** The adapter refuses to land a torrent asset whose
   `integrity` is not `verified` — a typed `INTEGRITY_FAILED` rejection,
   never a silent partial landing.
3. **PROVENANCE SURVIVES.** The asset-store sidecar records the torrent
   provenance (source id + authorization kind) as the asset's origin —
   invariant 5's audit trail survives the seam.

## What R12/R13/R14 consume

- **R12 (playback-aware scheduler)** consumes the engine's `prioritize`
  command (the byte-range → piece-deadline translation seam, currently a
  no-op recording; R12 wires the scheduler's deadline translation). The
  engine's `sessionGeometry()` (additive, not in the frozen surface) is
  the geometry the scheduler translates against.
- **R13 (torrent persistence/recovery)** consumes the engine's `recover()`
  for restart-resume and the journal's `extractRecoverableSessions` for
  cross-session replay. R13 also wires the verified-asset landing through
  the adapter into the Library.
- **R14 (native acquisition UX)** consumes the honest status projection
  (`HonestTorrentStatus`) for the user-facing `Available -> Preparing ->
  Buffering -> Playing -> Completing -> Ready offline -> Failed/Recoverable`
  states. The torrent protocol terminology stays behind the engine
  boundary; the UX surfaces product states only.

## What the lead must ratify

- The `AuthorizationKind` vocabulary (5 kinds) is in-package
  (`src/provenance.ts`). New kinds are added by lead-ratified extension
  (the provenance vocabulary stays in-package, not in `platform-contracts`).
- The `TorrentEngineErrorCode` taxonomy (10 codes) is the torrent-engine-
  LOCAL mirror of the R10 native-media `NativeMediaError` codes. The
  adapter maps these onto the native-media vocabulary before landing
  assets in the store.
- The `BitTorrentBackend` interface is the mature-library boundary. The
  production deployment wires a webtorrent-backed implementation behind
  it; the loopback is the TEST/DEV default (the documented testing mode).
  Ratifying the production backend is the lead's at R12 review (the
  sandbox cannot build webtorrent's `node_datachannel` native module).
